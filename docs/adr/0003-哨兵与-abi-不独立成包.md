# 0003 · 哨兵错误与 abi 常量不独立成包

- **状态**：已裁决（2026-10-22，QT-05 ④ 落 `engine/` 时；回答 `docs/API.md` §8 待裁 #1）
- **场景**：`ARCHITECTURE.md` §2 的包布局把 `errors/`（三类哨兵）与 `abi/`（host 函数版本 / 内存区 / 枚举上限）画成两个独立包，但 QT-05 ③-① 只要求迁 `domain/`、`engine/`、`fees/`，并明确 `engine/` 内保持 `package contracts`。今天哨兵（`ErrAbi*` / `ErrFillTiming*` / `ErrScope*` / `ErrActionIllegal` …）与 abi 常量（`HostFn*` / `HostAbiV*` / `HostRegion*` / 枚举上限）都住在 `pkg/backtest/contracts`。两张图口径不一致，落码前必须挑一条。
- **实测（2026-10-22，core 全仓 `grep -rl`，**不是估计**）**：
  - `contracts.Err*` 的消费方只有 **10 个文件**（非测试 4：`pkg/backtest/aliases.go`、`pkg/sandbox/wasm/abi_check.go`、`pkg/sandbox/wasm/on_bar_session.go`、`cmd/analysis/handlers_backtest.go`；测试 6）；
  - `contracts.Host*` 的消费方只有 **4 个文件**（全在 `pkg/sandbox/wasm/`：`abi_check.go`、`host_api.go`、`host_api_v2_pending.go` + 测试）；
  - **关键判据**：这两组消费方**没有任何一个文件只想要哨兵或只想要 abi**——每个文件同时用到 ≥2 个其它 `contracts.*` 符号（最少 2 个，最多 35 个）。⇒ 拆包**不会让任何调用点少 import 一个包**，只会让它们多 import 一个。
- **决策**：`errors/` 与 `abi/` **不独立成包**，随 `engine/` 走，仍是 `package contracts` 的一部分。`ARCHITECTURE.md` §2 的图按此订正。
- **理由**：
  1. 拆包对消费方是**净负担**：10 + 4 个文件全都在用同一包里的其它符号，拆出去只会让它们同时 import 两个包才能写一个 `errors.Is`；
  2. 这两组符号与四契约的消费方高度重合（都指向「一次回测的输入 / 输出 / 执行者」），没有独立的演化节奏；
  3. 真要拆，拆包本身是可排期的独立变更（加别名 = MINOR，改名 = MAJOR），**不必在 S1 的搬迁期顺带付**。
- **代价 / 后果**：`engine/` 成为一个 **10 文件 / 2543 行（非测试）**的包，导出面 **194** 个符号（占本仓 429 的 45%）。这是已知的粒度代价；判据是「包内是否有真实的独立演化需求」——今天没有，等到有（例如 abi 要独立发给 artifact 加载器）再拆。
- **⚠️ 一处被证伪的旧估计**：QT-05 前期笔记里写过「拆包会波及约 61 个 core 文件」。**实测是 4 个非测试文件 + 6 个测试文件**；61 这个数没有来源，已作废。结论不变，但理由换了：不是「改动太大」，而是「改了没人受益」。
- **替代关系**：订正 `ARCHITECTURE.md` §2 的 `errors/` / `abi/` 两行（不是新决策，是把图对齐到代码）
