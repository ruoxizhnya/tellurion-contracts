# 0004 · 值对象上的纯函数行为随类型走

- **状态**：已裁决（2026-10-22，QT-05 ③-① 迁 `pkg/domain` 时；澄清 [0001](0001-契约只增不破且零实现.md) ② 的适用范围，不废除它）
- **场景**：0001 ② 写「禁止任何实现」。但 S1 要整包迁 core 的 `pkg/domain`，包里有方法体：`FactorDefinition.Validate` / `VersionHash`、`CorporateAction.Apply`（5 种公司行为的纯变换）、`ActionEngine.ApplyAll`（按除权日排序并调度）。若「零实现」按「零方法体」解释，S1 的整包迁与 0001 直接冲突；若按「零服务 / 零引擎」解释，它们又不该被赶走。必须给出可执行的判据。
- **决策**：允许**值对象自带的纯函数行为**随类型迁入本仓。判据四条，**全部满足**才算：
  1. **无 I/O**：不读文件 / 网络 / 数据库，不取墙钟（时间必须由入参给出）；
  2. **依赖受限**：只 import 标准库 + 本仓包，不 import 任何应用仓或实现包；
  3. **无跨调用持久状态**：可以返回新值、可以持有**调用方语义**的进程内便利缓存，但不得把状态当真相（`ActionEngine.appliedLog` 是此类，文档已写明持久化归调用方）；
  4. **不替代服务**：没有回测循环 / 撮合 / 存储 / 调度器；一次调用只做一次局部变换或判定。
- **现有落点**（按上述判据逐条核过）：`FactorDefinition.Validate` / `FactorRegistration.Validate` / `FactorMiningRecord.Validate`（结构校验，无 I/O）、`FactorDefinition.VersionHash`（canonical JSON 的 SHA-256）、`CorporateAction.Apply` 及其 5 个实现（纯持仓 / 现金变换）、`ActionEngine.ApplyAll`（排序 + 逐条 Apply，状态由调用方持有）、`fees.AShareFees.ApplyDefaults` / `Validate`（填零值 / 区间判定）。
- **不在此列的**：回测引擎、撮合、存储、调度、HTTP / gRPC 服务、任何读过程的实现——0001 ② 对它们继续有效。
- **代价 / 后果**：本仓不是「只有声明、没有方法体」的纯 IDL；边界靠上面四条判据而不是「有没有方法」。新增方法必须按四条核；四条外的新形状（例如要读库、要接时钟）立新 ADR，不在本仓硬塞。
- **替代关系**：澄清 0001 ② 的适用范围，不替代 0001。
