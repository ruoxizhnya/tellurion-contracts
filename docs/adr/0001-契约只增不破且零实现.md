# 0001 · 契约只增不破且零实现

- **状态**：已裁决（来源：ADR-D29 §5 / ADR-D2 / QT-05）
- **场景**：最初的做法是"在 core 里改 struct，下游跟着改"。结果是每次调整都要同时动 core 与 agent，而且没人说得清哪些类型属于"跨边界"。契约层如果放进实现或业务规则，就会退化成公共代码堆放处，改一次牵动所有下游。
- **决策**：① 本仓只放被 ≥2 个仓使用的类型 / 接口 / 错误 / 常量；② 禁止任何实现与 DB 访问；③ 禁止 `Config` / `Options` / `Impl` 命名；④ 跨仓依赖只认版本号（tag / 伪版本），禁止 `replace` 指向仓外（**唯一过渡例外**：`tellurion-agent` 的 `replace tellurion => ../tellurion`，以 `tellurion-agent:docs/adr/0001-编译期依赖-core-是过渡态.md` 为准，S3 后收回；例外只放宽 replace 一条，"契约只增不破"红线不因此松动）。
- **理由**：契约是唯一跨仓缝隙，它必须"便宜到改一次只发一个版"。把实现放进来的诱惑很大（省一次搬家），但代价是所有下游被迫跟着理解实现细节 —— 那正是拆仓要消灭的东西。
- **代价 / 后果**：会出现临时膨胀：S1 整包迁 `domain` 时，`screen` / `sector` / `supply_chain` / `macro` / `mining` 只有 core 用（agent 侧 0 命中）。接受，并输出「core-only 类型清单」，S2 后按清单回收。
- **替代关系**：无（本仓首条）
